# CafeFlow — คู่มือดูแลระบบหน้าร้าน

เขียนสำหรับคนที่ต้องแก้ปัญหาตอนร้านเปิดไม่ได้ ไม่ใช่สำหรับคนที่เขียนโค้ด
อ่านหัวข้อที่ตรงกับอาการ แล้วทำตามทีละบรรทัด

---

## ร้านเปิดไม่ได้ — ทำอะไรก่อน

**อย่าเพิ่งแตะเซิร์ฟเวอร์ ให้ร้านขายได้ก่อน**

1. หยิบ **บิลกระดาษคาร์บอน** กับป้ายราคาที่พิมพ์ไว้ออกมาใช้ ขายด้วยเงินสดไปก่อน
2. เก็บบิลไว้ให้ครบทุกใบ เรียงตามลำดับ
3. ค่อยแก้ระบบ แล้วบันทึกออเดอร์ย้อนหลังทีหลัง

> ข้อนี้ไม่ใช่ทางเลือก — ไม่มีสถาปัตยกรรมไหนทำให้เครื่องไม่พัง
> ทำได้แค่ลดเวลาที่เสียไป **ถ้าไม่มีบิลกระดาษ วันที่เครื่องพังคือวันที่ร้านปิด**

ของที่ต้องมีอยู่ในลิ้นชักตลอด: บิลคาร์บอน · ป้ายราคาพิมพ์ · ปากกา · เบอร์คนดูแลระบบ

## เช็กเร็ว ๆ ว่าอะไรพัง

```bash
docker ps                                  # ฐานข้อมูลยังอยู่ไหม
curl http://localhost:8080/api/health      # API ตอบไหม
```

| อาการ | น่าจะเป็น | ไปที่ |
|---|---|---|
| `curl` ไม่ตอบเลย | API ไม่ได้รัน | สตาร์ท API ใหม่ (ล่าง) |
| `curl` ตอบ แต่หน้าจอว่าง | เบราว์เซอร์ต่อผิดเครื่อง | เช็ก IP ของ mini PC |
| ตอบว่า error เรื่องฐานข้อมูล | Postgres ไม่ขึ้น | `docker compose up -d db` |
| ทุกอย่างขึ้นแต่ข้อมูลหาย | ต้องกู้คืน | หัวข้อ "กู้คืน" |
| คีออสก์ขึ้น "สั่งที่เคาน์เตอร์" | เครือข่ายขาด | เช็กสาย LAN / Wi-Fi |
| ครัวไม่ได้ตั๋ว แต่ KDS มี | เครื่องพิมพ์ | หัวข้อ "เครื่องพิมพ์" |

### สตาร์ทใหม่ทั้งชุด
เปิดเองทุกครั้งที่ login (ตั้งไว้ด้วย `ops\install-autostart.ps1` — ทางลัด CafeFlow ในโฟลเดอร์ Startup)
สั่งเองก็ได้ เรียกซ้ำได้ ตัวไหนเปิดอยู่แล้วจะข้าม:
```powershell
powershell -ExecutionPolicy Bypass -File ops\start-cafeflow.ps1
```
ลำดับ: เปิด Docker Desktop → รอฐานข้อมูลพร้อม → API (8080) → ตัวอ่านสลิป (5101)
ดูว่าติดตรงไหน: `logs\start.log` · `logspi.log` · `logs\ocr.log`

⚠️ Windows ต้อง login เองตอนเปิดเครื่อง (Docker Desktop ทำงานเฉพาะตอนมีผู้ใช้ login)
ตั้งด้วย `netplwiz` → เอาติ๊ก "Users must enter a user name and password" ออก

## สำรองข้อมูล

```bash
ops/backup.sh            # สำรองหนึ่งครั้ง
ops/backup.sh --verify   # สำรองแล้วกู้ลงฐานชั่วคราวเพื่อพิสูจน์ว่าไฟล์ใช้ได้จริง
```

ไฟล์ไปอยู่ที่ `backup/cafeflow-YYYYMMDD-HHMMSS.dump` พร้อมไฟล์ `.counts`
ที่บันทึกจำนวนแถวของแต่ละตารางไว้ — ตอนกู้จะเอามาเทียบให้อัตโนมัติ

**ไฟล์สำรองที่ไม่เคยถูกกู้ ไม่นับว่าเป็นไฟล์สำรอง** จึงควรใช้ `--verify`
อย่างน้อยวันละครั้ง ไม่ใช่แค่ตอนติดตั้ง

### ตั้งให้ทำเอง

Linux (mini PC ในร้าน) — `crontab -e`:
```cron
# ทุกชั่วโมงระหว่างเวลาทำการ
0 8-21 * * *  cd /opt/cafeflow && ops/backup.sh            >> /var/log/cafeflow-backup.log 2>&1
# ตรวจสอบเต็มรูปแบบวันละครั้งหลังปิดร้าน
30 22 * * *   cd /opt/cafeflow && ops/backup.sh --verify   >> /var/log/cafeflow-backup.log 2>&1
```

เก็บย้อนหลัง 14 วัน (ปรับที่ `CF_BACKUP_KEEP_DAYS`)

## สำเนานอกเครื่อง

**ไฟล์สำรองที่อยู่ในเครื่องเดียวกับฐานข้อมูล ช่วยตอน "ลบข้อมูลผิด" ได้
แต่ช่วยตอน "ไฟไหม้ / เครื่องหาย / SSD พัง" ไม่ได้เลย**

```bash
ops/offsite.sh /d/cafeflow-backup          # USB หรือ NAS ที่ mount ไว้
ops/offsite.sh rclone:gdrive:cafeflow      # คลาวด์ผ่าน rclone
ops/offsite.sh --check /d/cafeflow-backup  # ตรวจว่าปลายทางมีครบและไฟล์ไม่เพี้ยน
```

ตั้ง `CF_OFFSITE=/d/cafeflow-backup` ไว้ใน `.env` แล้วเรียก `ops/offsite.sh` เปล่า ๆ ได้

**สิ่งที่สคริปต์นี้ระวังให้**
- **ตรวจ checksum ที่ปลายทางทุกไฟล์** — การคัดลอกที่ "ดูเหมือนสำเร็จ" แต่ไฟล์เสีย
  เกิดได้จริงกับ USB ที่ใกล้พัง และจะรู้ตัวก็ตอนต้องใช้ ซึ่งสายไปแล้ว
- **ไม่สร้างโฟลเดอร์ปลายทางถ้าโฟลเดอร์แม่ไม่มี** — USB ที่ยังไม่ได้เสียบจะทำให้ได้
  สำเนาที่อยู่ในเครื่องเดียวกันโดยที่คนสั่งนึกว่าออกไปข้างนอกแล้ว **อันตรายกว่าไม่มีสำเนา**
- เขียนเป็น `.part` ก่อนแล้วค่อยเปลี่ยนชื่อ — ถอด USB กลางคันจะเหลือไฟล์ที่เห็นชัดว่าไม่สมบูรณ์
  แทนที่จะเป็นไฟล์ชื่อถูกแต่ข้างในขาด
- คืนค่า exit ไม่เป็นศูนย์เมื่อล้มเหลว เพื่อให้ cron จับได้

### ตั้งให้ทำเอง (ต่อจากตาราง cron ด้านบน)

```cron
# คัดลอกออกนอกเครื่องหลังสำรองเสร็จ
45 22 * * *   cd /opt/cafeflow && ops/offsite.sh              >> /var/log/cafeflow-backup.log 2>&1
# ตรวจปลายทางเช้าวันจันทร์ — จะได้รู้ก่อนว่า USB เริ่มพัง
0 7 * * 1     cd /opt/cafeflow && ops/offsite.sh --check      >> /var/log/cafeflow-backup.log 2>&1
```

## กู้คืน

```bash
ops/restore.sh                      # จากไฟล์ล่าสุด
ops/restore.sh backup/xxx.dump      # จากไฟล์ที่ระบุ
```

จะถามยืนยันด้วยการพิมพ์ `YES` เพราะ **ข้อมูลปัจจุบันจะถูกลบทิ้งทั้งหมด**

### เครื่องพังทั้งเครื่อง ต้องขึ้นเครื่องใหม่

```bash
# 1. ลง Docker + Node บนเครื่องใหม่ แล้วคัดลอกโฟลเดอร์โปรเจกต์กับ backup/ มา
# 2. ตั้ง .env ให้เหมือนเดิม (คัดลอกมาจากเครื่องเก่าหรือจาก .env.example)
docker compose up -d db
cd api && npm install && npm run migrate
cd .. && ops/restore.sh --yes
cd api && npm start
# 3. ตั้ง IP ของเครื่องใหม่ให้ตรงกับที่แคชเชียร์/KDS/คีออสก์ชี้อยู่
#    (ง่ายกว่าไปไล่แก้ทุกเครื่อง)
```

### ผลการซ้อมจริง

ซ้อมเมื่อ 19 ก.ย. 2569 โดยลบ volume ของฐานข้อมูลทิ้งทั้งหมด:

| ขั้น | ผล |
|---|---|
| ลบ volume แล้วเปิดใหม่ | ฐานว่างเปล่า `relation "cf_order" does not exist` |
| `ops/restore.sh --yes` | **12 วินาที** · จำนวนแถวตรงทุกตาราง |
| ล็อกอินด้วยรหัสเดิม | ได้ |
| สั่งออเดอร์ใหม่ | ได้เลข **A010** เดินต่อจาก A009 ไม่ชนกัน |
| รับเงิน | สำเร็จ |

เลขออเดอร์เดินต่อถูกเพราะตาราง `order_seq` ถูกกู้มาด้วย — ถ้าตัวนับหาย
ระบบจะออกเลขซ้ำกับบิลที่พิมพ์ไปแล้ว ซึ่งเป็นปัญหาทางบัญชี ไม่ใช่แค่ความสวยงาม

**ควรซ้อมซ้ำทุกครั้งที่อัปเกรด Postgres หรือเปลี่ยนโครงฐานข้อมูลครั้งใหญ่**

## สิ่งที่แผนสำรองนี้ยัง **ไม่** ครอบคลุม

| ช่องว่าง | ผลที่เกิด | ทางแก้เมื่อพร้อม |
|---|---|---|
| สำรองเป็นช่วง ๆ ไม่ใช่ต่อเนื่อง | ข้อมูลระหว่างการสำรองครั้งล่าสุดถึงตอนพัง **หายจริง** (สูงสุด 1 ชั่วโมงตามตาราง cron) | เปิด WAL archiving (`pg_receivewal`) ลดเหลือระดับวินาที |
| ไม่มีเครื่องสำรองพร้อมใช้ | ต้องหาเครื่อง ลงของ แล้วค่อยกู้ — หลายชั่วโมง | เตรียม mini PC เครื่องสองที่ลง image เดียวกันไว้ในลิ้นชัก |
| ไฟล์สำรองยังอยู่ในเครื่องเดียวกัน | ไฟไหม้/ของหาย = หายทั้งคู่ | **มีเครื่องมือแล้ว** (`ops/offsite.sh`) — เหลือแค่เสียบ USB หรือตั้ง rclone แล้วใส่ใน cron |

พูดตรง ๆ: ตอนนี้ **RPO ประมาณ 1 ชั่วโมง · RTO ประมาณ 15 นาที** ถ้ามีเครื่องพร้อม

## เครื่องพิมพ์

### ตั้งค่า

หน้าภาพรวม › ปุ่ม **เครื่องพิมพ์** (ผู้จัดการ/แอดมินเท่านั้น) — เพิ่ม/แก้เครื่อง และดูว่าแต่ละส่วนพิมพ์ออกที่ไหน
ส่วนที่ไม่มีเครื่องของตัวเองจะพิมพ์ออกที่เครื่องเคาน์เตอร์ (เครื่องที่ช่อง "ใช้พิมพ์ของส่วน" เป็นใบเสร็จ/เคาน์เตอร์)

| ต่อแบบ | ใช้เมื่อ | ต้องเตรียม |
|---|---|---|
| **LAN / IP** | เครื่องพิมพ์อยู่จุดไหนในร้านก็ได้ | ตั้ง IP ของเครื่องพิมพ์ให้คงที่ · พอร์ตปกติ 9100 |
| **USB** | เครื่องพิมพ์เสียบกับ **เครื่องเซิร์ฟเวอร์** เท่านั้น | Windows: ลงไดรเวอร์ให้ขึ้นใน Printers & scanners ก่อน แล้วเลือกจากรายการ · Linux: user ที่รัน API ต้องอยู่กลุ่ม `lp` (`sudo usermod -aG lp <user>`) แล้วเลือก `/dev/usb/lp0` |

เครื่องพิมพ์ USB ที่เสียบกับเครื่องอื่น (เช่นเครื่องคีออสก์) **ใช้ไม่ได้** — เซิร์ฟเวอร์เป็นคนส่งงานพิมพ์ ไม่ใช่เบราว์เซอร์

### ตั๋วไม่ออก

ครัวไม่ได้ตั๋วแต่ KDS เห็นออเดอร์ = ปัญหาอยู่ที่เครื่องพิมพ์ ไม่ใช่ที่ระบบ

1. เช็กของจริงก่อน: **กระดาษหมด · ฝาเปิดไม่สนิท · สายหลุด · ไฟไม่เข้า**
2. ดูคิวที่ค้าง:
   ```bash
   curl -b cookie.txt http://localhost:8080/api/print/queue
   ```
3. แก้ของจริงเสร็จแล้วสั่งพิมพ์ซ้ำ:
   ```bash
   curl -X POST -b cookie.txt http://localhost:8080/api/print/jobs/<id>/retry
   ```

ระบบลองเอง 3 ครั้งแล้วตกไปเครื่องสำรองให้อัตโนมัติ ถ้ายังไม่ได้ถึงจะขึ้นเป็น `FAILED`

> **ข้อจำกัดที่ต้องรู้**: เครื่องพิมพ์ความร้อนผ่าน TCP 9100 หรือ USB ไม่ตอบอะไรกลับ
> ระบบยืนยันได้แค่ว่า "ส่งถึงเครื่องแล้ว" **ไม่ใช่ว่ากระดาษออก**
> กระดาษหมดก็ขึ้น `DONE` เหมือนกัน — จึงต้องมีคนดูหน้าเครื่องอยู่ดี

## QR ออกไม่ได้

ขึ้นว่า "ยังไม่ได้ตั้งพร้อมเพย์ของร้าน" → ไปที่ **หน้าภาพรวม › ตั้งค่าคีออสก์ ›
พร้อมเพย์ของร้าน** ใส่เบอร์โทร 10 หลักหรือเลขผู้เสียภาษี 13 หลัก

ถ้าออก QR ไม่ได้ด้วยเหตุอื่น คีออสก์จะขึ้น "กรุณาชำระที่เคาน์เตอร์" ให้เอง
ร้านยังขายต่อได้ ไม่ต้องรีบแก้กลางชั่วโมงเร่ง

## กล้องสแกนสลิปที่คีออสก์

ลูกค้าจ่าย QR แล้วกด "โอนแล้ว · สแกนสลิป" → ยกจอมือถือที่เปิดสลิปให้กล้องอ่าน QR มุมสลิป
ระบบกันสลิปใบเดิมใช้ซ้ำ แล้วส่งออเดอร์ไป **รอแคชเชียร์ยืนยัน** — ครัวยังไม่ได้ออเดอร์จนกว่าแคชเชียร์
เห็นเงินเข้าบัญชีร้านแล้วกดยืนยัน (QR บนสลิปมีแค่เลขอ้างอิง ไม่มียอดเงิน จึงพิสูจน์เงินเข้าไม่ได้)

### ตั้งเครื่องคีออสก์ (ครั้งเดียว)

1. เสียบกล้อง (เว็บแคม USB ตัวไหนก็ได้ 720p ขึ้นไป) หันออกหาลูกค้า ระดับอก
2. คัดลอก `ops/kiosk-edge.bat` ไปไว้ที่เครื่องคีออสก์ แก้บรรทัด `SERVER=` เป็น IP ของเครื่องเซิร์ฟเวอร์
3. เปิดคีออสก์ด้วยไฟล์นี้เท่านั้น (ใส่ทางลัดไว้ใน `shell:startup` ให้เปิดเองตอนบูต)
4. จับคู่เครื่องด้วยรหัสจากหน้าภาพรวม › อุปกรณ์ ตามปกติ

**ทำไมต้องเปิดด้วยไฟล์นี้:** เบราว์เซอร์ยอมให้ใช้กล้องเฉพาะหน้าเว็บ https เซิร์ฟเวอร์ร้านเป็น http
ไฟล์นี้บอกเบราว์เซอร์ให้เชื่อ *เฉพาะ* เซิร์ฟเวอร์ร้าน และอนุญาตกล้องให้อัตโนมัติ (ไม่มีคนยืนกด "อนุญาต")
ถ้าเปิดคีออสก์แบบอื่น หน้าสแกนจะขึ้น "กล้องของเครื่องนี้ยังใช้ไม่ได้" แล้วให้ลูกค้าแจ้งพนักงาน — ร้านยังขายได้

| อาการ | แก้ |
|---|---|
| ขึ้น "กล้องของเครื่องนี้ยังใช้ไม่ได้" | ไม่ได้เปิดด้วย `kiosk-edge.bat` หรือ IP ใน `SERVER=` ไม่ตรงกับที่เปิดอยู่ |
| ขึ้น "เปิดกล้องไม่ได้" | กล้องหลุด / โปรแกรมอื่นใช้กล้องอยู่ |
| สแกนนานไม่ติด / ภาพสลิปเบลอบ่อย | ใช้เว็บแคมที่ **โฟกัสอัตโนมัติ (autofocus)** 1080p — กล้องโฟกัสตายตัวจะเบลอที่ระยะ 20–30 ซม. เสมอ · ไม่หันกล้องรับไฟเพดานตรง ๆ (จอมือถือสะท้อน) |
| "สลิปนี้ถูกใช้ชำระออเดอร์อื่นไปแล้ว" | ลูกค้าเอาสลิปเก่ามาใช้ — ดูประวัติได้ที่ audit (`SLIP_REJECTED`) |

### ตัวอ่านสลิป (OCR)

กล้องถ่ายภาพสลิปเก็บไว้ แล้วตัวอ่านสลิป (`ocr-svc/`, PaddleOCR) อ่าน **ยอดเงินกับวันที่** จากภาพ
เบื้องหลังราว 5 วินาที การ์ดแคชเชียร์ขึ้นผลเอง: เขียว = ตรง · **แดง = ยอด/วันที่ไม่ตรง** · เทา = อ่านไม่ออก
ตอนอ่าน QR ได้ กล้องเก็บภาพต่ออีก ~0.6 วินาทีแล้วเลือกภาพที่คมที่สุด · ถ้า OCR อ่านยอดไม่ออก
หรือไม่เห็นวันที่ (ถือให้กล้องเห็นแค่ครึ่งล่าง) คีออสก์โชว์ภาพที่ถ่ายได้ + บอกว่าต้องแก้อะไร
ลูกค้ากด "ถ่ายใหม่" ได้เรื่อย ๆ หรือ "ส่งให้พนักงานตรวจ" · ทิ้งไว้ 60 วิส่งให้พนักงานเอง
คีออสก์รอผลนี้ด้วย (นานสุด 15 วินาที): ยอด/วันที่ไม่ตรง → ขึ้นกล่องแดงบอกลูกค้าให้สแกนใบที่ถูก
หรือแจ้งพนักงาน · ผ่าน/อ่านไม่ออก/ตัวอ่านไม่ตอบ → ไปรอแคชเชียร์ตามปกติ (ลูกค้าไม่ติดหน้าเครื่อง)
ผลนี้ช่วยเตือนเท่านั้น ไม่ยืนยันเงินเข้าแทนคน และไม่ส่งออเดอร์เข้าครัวเอง

ติดตั้งครั้งเดียวบนเครื่องเซิร์ฟเวอร์ **ตอนยังมีเน็ต** (หลังจากนั้นใช้แบบไม่มีเน็ตได้):
1. ลง Python 3.11 จาก python.org (ติ๊ก "Add to PATH")
2. ดับเบิลคลิก `ocr-svc\setup.bat` — โหลดราว 900 MB รอจนขึ้น "Done"
3. ไม่ต้องตั้งแยก — `ops\start-cafeflow.ps1` เปิดตัวอ่านสลิปให้ด้วย (ถ้าติดตั้งไว้)

เช็กว่าทำงานอยู่: `curl http://127.0.0.1:5101/health` · ใช้แรม ~1 GB · อ่านทีละใบ

**ถ้าตัวอ่านสลิปไม่ได้เปิด ร้านขายได้ปกติ** — สลิปรอในคิว แล้วอ่านต่อเองเมื่อเปิดกลับมา
ภาพสลิปอยู่ที่ `data/slips/` (มีชื่อ/เลขบัญชีบางส่วนของลูกค้า ห้ามแชร์ออกนอกร้าน)
`ops/backup.sh` สำรองโฟลเดอร์ `data/` ไปที่ `backup/data/` ด้วย (คัดลอกเฉพาะไฟล์ใหม่) · `offsite.sh` คัดลอกตามไป · `restore.sh` คืนให้

## คำสั่งที่ใช้บ่อย

```bash
# ดูออเดอร์ที่ยังไม่จบ
docker exec -it cafeflow-db psql -U cafeflow -d cafeflow -c \
  "SELECT order_no, status, total FROM cf_order
    WHERE status NOT IN ('COMPLETED','CANCELLED','VOIDED','REFUNDED')
    ORDER BY created_at;"

# ดูรอบขายที่เปิดอยู่
docker exec -it cafeflow-db psql -U cafeflow -d cafeflow -c \
  "SELECT id, opened_at, opening_cash FROM shift WHERE status = 'OPEN';"

# ดู log ของ API
docker compose logs -f db          # ฐานข้อมูล
# API รันนอก container — ดูที่ terminal ที่สั่ง npm start
```

**ห้ามแก้ข้อมูลด้วย SQL ตรง ๆ ถ้าไม่จำเป็นจริง ๆ** — ทุกการเปลี่ยนสถานะที่ผ่าน
ระบบจะมี audit log กำกับ แต่การแก้ตรงในฐานจะไม่มี และตรวจย้อนหลังไม่ได้ว่าใครทำ
