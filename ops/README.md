# CafeFlow — คู่มือดูแลระบบหน้าร้าน

เขียนสำหรับคนที่ต้องแก้ปัญหาตอนร้านเปิดอยู่ ไม่ใช่สำหรับคนที่เขียนโค้ด — อ่านหัวข้อที่ตรงกับอาการ แล้วทำทีละบรรทัด
**ติดตั้งร้านใหม่ / ย้ายเครื่อง / ตั้งค่าครั้งแรก → [`INSTALL.md`](../INSTALL.md)**

ระบบทั้งหมดอยู่บน Windows: เครื่องเซิร์ฟเวอร์รัน PostgreSQL ใน Docker Desktop + API (Node, พอร์ต 8080) + ตัวอ่านสลิป (Python, พอร์ต 5101)
โฟลเดอร์ `D:\cafeflow` (เครื่องที่ไม่มีไดรฟ์ D อยู่ที่ `C:\cafeflow`) — คำสั่งในคู่มือนี้รันจากโฟลเดอร์นี้

## เมนูดูแลระบบ — ไฟล์เดียวพอ

**เครื่องเซิร์ฟเวอร์: ดับเบิลคลิกไอคอน CafeFlow บน Desktop** (= `ops\cafeflow.bat`) → กดลูกศร ↑ ↓ เลือก แล้ว Enter (หรือกดตัวเลข · Esc ออก)

| กลุ่ม | ข้อในเมนู | ใช้เมื่อ |
|---|---|---|
| ใช้ประจำ | **ตรวจสถานะระบบ** | ดูก่อนเมื่อหน้าร้านมีปัญหา — API · ฐานข้อมูล · ตัวอ่านสลิป · IP ร้าน |
| | **รีสตาร์ทระบบ (API + ตัวอ่านสลิป)** | หน้าเว็บค้าง · เพิ่งอัปเดต · ปุ่มใหม่ขึ้น "Route … not found" |
| | **ดูที่อยู่เครื่องเซิร์ฟเวอร์ (IP)** | ตั้งจอเครื่องใหม่ (กรอกใน `screen-edge.bat`) |
| | **เปิดจอบนเครื่องนี้** | ใช้เครื่องเซิร์ฟเวอร์เป็นคีออสก์ / แคชเชียร์ / ครัว / จอคิวด้วย |

| | **ดู log ล่าสุด** | ท้าย log การเปิดระบบ · สำรองข้อมูล · ข้อผิดพลาด · API — ถ่ายรูปส่งช่างได้ |

| | **ตั้งให้ระบบเปิดเองตอนเปิดเครื่อง** | งานใน Task Scheduler หาย / ถูกแอนตี้ไวรัสลบ |
| | **เปลี่ยนรหัสผ่านฐานข้อมูล** | ครั้งเดียวตอนติดตั้ง |
| | **วัดความเร็วตัวอ่านสลิป** | เทียบตัวอ่าน 2 แบบกับสลิปของร้าน (ไม่เปลี่ยนอะไร) |
| | **ติดตั้งซ้ำ / ซ่อมระบบ** | ตรวจ Git · Node · Python · Docker · ฐานข้อมูล · ตัวอ่านสลิป · ไฟร์วอลล์ ทำเฉพาะส่วนที่ขาด |

เมนูเปิดไม่ขึ้น → ไฟล์ย่อยใน `ops\tools\` ดับเบิลคลิกตรงได้: `restart-api.bat` (รีสตาร์ท) · `bench-ocr.bat` (วัดตัวอ่านสลิป) · ซ่อมระบบ: `ops\cafeflow.bat install`
**เครื่องอื่น** (คีออสก์ / แคชเชียร์ / ครัว / จอคิว) ใช้ `ops\screen-edge.bat` ตัวเดียว — ดูหัวข้อ "เปิดจอแต่ละเครื่อง"

## ร้านเปิดไม่ได้ — ทำอะไรก่อน

**อย่าเพิ่งแตะเซิร์ฟเวอร์ ให้ร้านขายได้ก่อน**

1. หยิบ **บิลกระดาษคาร์บอน** กับป้ายราคาที่พิมพ์ไว้ออกมาใช้ ขายด้วยเงินสดไปก่อน
2. เก็บบิลไว้ให้ครบทุกใบ เรียงตามลำดับ
3. ค่อยแก้ระบบ แล้วบันทึกออเดอร์ย้อนหลังทีหลัง

> ข้อนี้ไม่ใช่ทางเลือก — ไม่มีสถาปัตยกรรมไหนทำให้เครื่องไม่พัง
> ทำได้แค่ลดเวลาที่เสียไป **ถ้าไม่มีบิลกระดาษ วันที่เครื่องพังคือวันที่ร้านปิด**

ของที่ต้องมีอยู่ในลิ้นชักตลอด: บิลคาร์บอน · ป้ายราคาพิมพ์ · ปากกา · เบอร์คนดูแลระบบ

แล้วค่อยแก้ตามลำดับ: ไอคอน CafeFlow › **ตรวจสถานะระบบ** → **รีสตาร์ทระบบ** → ยังไม่ได้ ปิด-เปิดเครื่องเซิร์ฟเวอร์ รอ 3 นาที → ยังไม่ได้ **ดู log ล่าสุด** ส่งช่าง

## เช็กเร็ว ๆ ว่าอะไรพัง

ทางง่าย: ไอคอน CafeFlow › **ตรวจสถานะระบบ** (✓ ทุกบรรทัด = ปกติ · ✗ บอกว่าตัวไหนพัง)
ทางช่าง — PowerShell ที่เครื่องเซิร์ฟเวอร์ (ใช้ `curl.exe` เต็มชื่อ — `curl` เฉย ๆ ใน PowerShell 5 คือคำสั่งอื่น):
```powershell
docker ps                                       # ต้องเห็น cafeflow-db สถานะ Up (healthy)
curl.exe http://localhost:8080/api/health       # API ตอบไหม — ต้องมี "ok":true
curl.exe http://127.0.0.1:5101/health           # ตัวอ่านสลิป — "engine": "openvino" หรือ "paddleocr"
```

| อาการ | น่าจะเป็น | ไปที่ |
|---|---|---|
| health ไม่ตอบเลย | API ไม่ได้รัน | เมนู **รีสตาร์ทระบบ** |
| `docker ps` error / ไม่มี cafeflow-db | Docker Desktop ไม่เปิด | เปิด Docker Desktop รอ Engine running → `docker compose up -d db` |
| health ตอบ แต่จออื่นว่าง | จอต่อผิด IP / ไฟร์วอลล์ | เมนู **ดูที่อยู่เครื่องเซิร์ฟเวอร์** เทียบกับที่จอบันทึกไว้ (`screen-edge.bat ip`) · ไฟร์วอลล์ → **ติดตั้งซ้ำ / ซ่อมระบบ** |
| ตอบว่า error เรื่องฐานข้อมูล | Postgres ไม่ขึ้น | `docker compose up -d db` |
| ทุกอย่างขึ้นแต่ข้อมูลหาย | ต้องกู้คืน | หัวข้อ "กู้คืน" |
| คีออสก์ขึ้น "สั่งที่เคาน์เตอร์" | เครือข่ายขาด | เช็กสายแลน / Wi‑Fi / เราเตอร์ |
| ครัวไม่ได้ตั๋ว แต่จอครัวมี | เครื่องพิมพ์ | หัวข้อ "เครื่องพิมพ์" |

### ระบบเปิดเองอย่างไร
ทุกครั้งที่ login เข้า Windows งาน Task Scheduler ชื่อ **CafeFlow** เรียก `ops\run-cafeflow.ps1`
(ตั้งด้วยเมนู **ตั้งให้ระบบเปิดเองตอนเปิดเครื่อง** = `node ops\tools\install-autostart.js` · ถอน: `--remove`)
สั่งเองก็ได้ เรียกซ้ำได้ ตัวไหนเปิดอยู่แล้วจะข้าม:
```powershell
schtasks /Run /TN CafeFlow
```
ลำดับ: เปิด Docker Desktop → รอฐานข้อมูลพร้อม → API (8080) → ตัวอ่านสลิป (5101)
**ขั้นไหนไม่ติดจะรอแล้วลองใหม่เรื่อย ๆ จนกว่าจะติด** (เว้น 10 → 20 → … สูงสุด 60 วิ)
- Docker ไม่พร้อมใน 3 นาที → ปิด Docker Desktop แล้วเปิดใหม่ให้เอง
- API เปิดแล้วตาย → ลองใหม่ · ตัวอ่านสลิปลองแค่ 5 ครั้ง (ไม่มีก็ขายได้)
- กดเปิดซ้ำระหว่างที่ตัวแรกยังทำงาน ตัวที่สองจะออกเองทันที

ดูว่าติดตรงไหน: `logs\start.log` · `logs\api.log` / `logs\api.err.log` · `logs\ocr.log` / `logs\ocr.err.log` (รอบก่อนหน้าอยู่ใน `*.prev.log`)
งานไม่ทำงานเลย → Task Scheduler › **CafeFlow** › Last Run Result (`0` = สำเร็จ) · งานหาย → แอนตี้ไวรัสลบ ดู [`INSTALL.md`](../INSTALL.md) ข้อ 3.1 แล้วตั้งใหม่จากเมนู

⚠️ Windows ต้อง login เองตอนเปิดเครื่อง (Docker Desktop ทำงานเฉพาะตอนมีผู้ใช้ login) — [`INSTALL.md`](../INSTALL.md) ข้อ 3.2

## อัปเดตระบบ

ไอคอน CafeFlow › **อัปเดตระบบเป็นรุ่นใหม่** — ต้องมีเน็ต · ทำตอนร้านไม่มีลูกค้า (ระบบหยุดราว 1 นาที)
ทำให้ครบในครั้งเดียว: สำรองข้อมูล → `git pull` → ลงไลบรารี (เฉพาะเมื่อเปลี่ยน) → อัปเดตโครงฐานข้อมูล → รีสตาร์ท แล้วรอจนระบบตอบ
✅ `✓ อัปเดตเสร็จ — ระบบทำงานด้วยรุ่นใหม่แล้ว` · หน้าเว็บที่เปิดค้าง (แคชเชียร์ · ครัว · ตู้) โหลดรุ่นใหม่เอง
❌ ล้มขั้นไหนจะบอกว่าต้องทำอะไร · `git pull` ไม่สำเร็จ = มีคนแก้ไฟล์ในเครื่องเอง หรือเน็ตหลุด — ยังไม่ได้เปลี่ยนอะไร ถ่ายรูปส่งช่าง

## ล้างข้อมูลขาย (ก่อนเปิดร้านจริง)

ไอคอน CafeFlow › **ล้างข้อมูลขาย (ก่อนเปิดร้านจริง)** (= `cd api; npm run clear-tx`)
แสดงจำนวนที่จะลบ → ถามว่าสำรองก่อนไหม (Enter = สำรอง) · ลบไฟล์สำรองเก่าไหม (Enter = เก็บ) → พิมพ์ `YES` (พิมพ์อย่างอื่น = ยกเลิก)
- **ลบ:** ออเดอร์ · การชำระ · ภาพสลิป · รอบขาย · ประวัติ
- **เก็บ:** เมนู · ราคา · ผู้ใช้ · อุปกรณ์ที่จับคู่แล้ว · เครื่องพิมพ์ · ค่าตั้งทั้งหมด
- เสร็จแล้ว: รีเฟรชทุกจอ → หน้า **ปิดรอบ / ปิดวัน** กด **เปิดรอบ** ก่อนตู้รับออเดอร์

## สำรองข้อมูล

ทำเองอัตโนมัติ 2 ทาง ด้วย `ops\backup.js` (Node — ไม่ต้องมี Git Bash):
- **ทุกคืน 23:30** — งาน Task Scheduler **CafeFlow Backup** (เครื่องปิดตอนนั้น = ทำตอนเปิดเครื่องครั้งถัดไป)
- **ทุกครั้งที่ปิดรอบสำเร็จ** — ยอดของรอบนั้นอยู่ในไฟล์สำรองทันที

สั่งเอง: ไอคอน CafeFlow › **สำรองข้อมูลตอนนี้** (= `node ops\backup.js`)

ไฟล์ไปอยู่ที่ `backup\cafeflow-YYYYMMDD-HHMMSS.dump` พร้อม `.counts` (จำนวนแถวแต่ละตาราง — ตอนกู้เอามาเทียบให้อัตโนมัติ)
และคัดลอกภาพสลิป/รูปสินค้า `data\` ไปที่ `backup\data\` (เฉพาะไฟล์ใหม่) · เก็บย้อนหลัง 30 วัน (`CF_BACKUP_KEEP_DAYS` ใน `.env`)
log: `logs\backup.log` · หน้าภาพรวมขึ้นเตือนถ้าไม่ได้สำรองเกิน 2 วัน

### พิสูจน์ว่าไฟล์สำรองใช้ได้จริง
**ไฟล์สำรองที่ไม่เคยถูกกู้ ไม่นับว่าเป็นไฟล์สำรอง** — เดือนละครั้ง และหลังอัปเดตใหญ่ ให้ตรวจ:
เปิดโฟลเดอร์ `D:\cafeflow` → คลิกขวาที่ว่าง › **Open Git Bash here** (Git Bash ติดมากับ Git ที่ลงตอนติดตั้ง) →
```bash
ops/tools/backup.sh --verify   # สำรองแล้วกู้ลงฐานชั่วคราว เทียบจำนวนแถว — ไม่แตะฐานจริง
```
✅ ทุกตารางตรง · ⚠️ `backup.sh` ลบไฟล์ `.dump` ที่เก่ากว่า 14 วันทิ้งด้วย (ค่าเริ่มต้นต่างจาก `backup.js`) — ถ้าอยากเก็บ 30 วัน ใส่ `CF_BACKUP_KEEP_DAYS=30` นำหน้าคำสั่ง

## สำเนานอกเครื่อง

**ไฟล์สำรองที่อยู่ในเครื่องเดียวกับฐานข้อมูล ช่วยตอน "ลบข้อมูลผิด" ได้
แต่ช่วยตอน "ไฟไหม้ / เครื่องหาย / SSD พัง" ไม่ได้เลย**

ใช้ `ops/tools/offsite.sh` — เป็นสคริปต์ bash รันใน **Git Bash** (คลิกขวาในโฟลเดอร์ `D:\cafeflow` › Open Git Bash here)
ใน Git Bash ไดรฟ์ USB `E:\` เขียนเป็น `/e/`:
```bash
ops/tools/offsite.sh /e/cafeflow-backup          # USB หรือ NAS ที่ map เป็นไดรฟ์
ops/tools/offsite.sh rclone:gdrive:cafeflow      # คลาวด์ผ่าน rclone (ต้องลง rclone เอง)
ops/tools/offsite.sh --check /e/cafeflow-backup  # ตรวจว่าปลายทางมีครบและไฟล์ไม่เพี้ยน
```
ตั้ง `CF_OFFSITE=/e/cafeflow-backup` ใน `.env` แล้วเรียก `ops/tools/offsite.sh` เปล่า ๆ ได้ · ปลายทางเก็บ 30 วัน (`CF_OFFSITE_KEEP`)
**แนะนำ: ทุกสัปดาห์** เสียบ USB → รันคำสั่งบน → ถอดเก็บนอกร้าน

**สิ่งที่สคริปต์นี้ระวังให้**
- **ตรวจ checksum ที่ปลายทางทุกไฟล์** — การคัดลอกที่ "ดูเหมือนสำเร็จ" แต่ไฟล์เสีย
  เกิดได้จริงกับ USB ที่ใกล้พัง และจะรู้ตัวก็ตอนต้องใช้ ซึ่งสายไปแล้ว
- **ไม่สร้างโฟลเดอร์ปลายทางถ้าโฟลเดอร์แม่ไม่มี** — USB ที่ยังไม่ได้เสียบจะทำให้ได้
  สำเนาที่อยู่ในเครื่องเดียวกันโดยที่คนสั่งนึกว่าออกไปข้างนอกแล้ว **อันตรายกว่าไม่มีสำเนา**
- เขียนเป็น `.part` ก่อนแล้วค่อยเปลี่ยนชื่อ — ถอด USB กลางคันจะเหลือไฟล์ที่เห็นชัดว่าไม่สมบูรณ์
  แทนที่จะเป็นไฟล์ชื่อถูกแต่ข้างในขาด
- คืนค่า exit ไม่เป็นศูนย์เมื่อล้มเหลว — Task Scheduler บันทึกเป็น Last Run Result ที่ไม่ใช่ 0

### ตั้งให้ทำเอง (ปลายทางที่เสียบ/ต่อไว้ตลอด เช่น NAS หรือ rclone)
ตั้ง `CF_OFFSITE` ใน `.env` ก่อน แล้วสร้างงาน Task Scheduler — PowerShell **แบบ admin**:
```powershell
# คัดลอกออกนอกเครื่องทุกคืน 23:45 (หลังสำรอง 23:30)
schtasks /Create /TN "CafeFlow Offsite" /SC DAILY /ST 23:45 /F /TR "\"C:\Program Files\Git\bin\bash.exe\" -lc 'cd /d/cafeflow && ops/tools/offsite.sh >> logs/offsite.log 2>&1'"
# ตรวจปลายทางเช้าวันจันทร์ — จะได้รู้ก่อนว่า USB/NAS เริ่มพัง
schtasks /Create /TN "CafeFlow Offsite Check" /SC WEEKLY /D MON /ST 07:00 /F /TR "\"C:\Program Files\Git\bin\bash.exe\" -lc 'cd /d/cafeflow && ops/tools/offsite.sh --check >> logs/offsite.log 2>&1'"
```
(เครื่องที่อยู่ `C:\cafeflow` เปลี่ยน `/d/cafeflow` เป็น `/c/cafeflow`)
ทดสอบทันที: `schtasks /Run /TN "CafeFlow Offsite"` แล้วเปิด `logs\offsite.log` ต้องเห็นผลการคัดลอก · ถอน: `schtasks /Delete /TN "CafeFlow Offsite" /F`

Git Bash ในโฟลเดอร์ `D:\cafeflow` (Docker Desktop ต้องเปิดอยู่):
```bash
ops/tools/restore.sh                      # จากไฟล์ล่าสุดใน backup/
ops/tools/restore.sh backup/xxx.dump      # จากไฟล์ที่ระบุ
```
ถามยืนยันด้วยการพิมพ์ `YES` · ตัดการเชื่อมต่อของ API ให้เอง · คืนภาพสลิป/รูปสินค้าจาก `backup/data/` (เฉพาะไฟล์ที่หาย) · เทียบจำนวนแถวกับ `.counts`
✅ `✓ ตรงกับตอนสำรองทุกตาราง` → ไอคอน CafeFlow › **รีสตาร์ทระบบ**
(สคริปต์จะบอกให้ `cd api && npm start` — บนเครื่องร้านใช้ **รีสตาร์ทระบบ** แทน ระบบจะเปิดแบบเบื้องหลังตามปกติ)

### เครื่องพังทั้งเครื่อง ต้องขึ้นเครื่องใหม่
ติดตั้งเครื่องใหม่ด้วย `ops\cafeflow.bat` ตาม [`INSTALL.md`](../INSTALL.md) ข้อ 2 → เอาโฟลเดอร์ `backup\` (จาก USB สำเนานอกเครื่อง) มาวางที่ `D:\cafeflow\backup\` → กู้ตาม [`INSTALL.md`](../INSTALL.md) ข้อ 7
ตั้ง IP ของเครื่องใหม่ที่เราเตอร์ให้ **ตรงกับ IP เดิม** ที่แคชเชียร์ / จอครัว / คีออสก์ชี้อยู่ (ง่ายกว่าไปไล่แก้ทุกเครื่อง)

### ผลการซ้อมจริง

ซ้อมเมื่อ 19 ก.ย. 2569 โดยลบ volume ของฐานข้อมูลทิ้งทั้งหมด:

| ขั้น | ผล |
|---|---|
| ลบ volume แล้วเปิดใหม่ | ฐานว่างเปล่า `relation "cf_order" does not exist` |
| `ops/tools/restore.sh --yes` | **12 วินาที** · จำนวนแถวตรงทุกตาราง |
| ล็อกอินด้วยรหัสเดิม | ได้ |
| สั่งออเดอร์ใหม่ | ได้เลข **A010** เดินต่อจาก A009 ไม่ชนกัน |
| รับเงิน | สำเร็จ |

เลขออเดอร์เดินต่อถูกเพราะตาราง `order_seq` ถูกกู้มาด้วย — ถ้าตัวนับหาย
ระบบจะออกเลขซ้ำกับบิลที่พิมพ์ไปแล้ว ซึ่งเป็นปัญหาทางบัญชี ไม่ใช่แค่ความสวยงาม

**ควรซ้อมซ้ำทุกครั้งที่อัปเกรด Postgres หรือเปลี่ยนโครงฐานข้อมูลครั้งใหญ่** (ซ้อมแบบไม่แตะฐานจริง: `ops/tools/backup.sh --verify`)

## เครื่องพิมพ์

### ตั้งค่า

⚙ › **เครื่องพิมพ์** (ผู้จัดการ/แอดมิน) — เพิ่ม/แก้เครื่อง และดูว่าแต่ละส่วนพิมพ์ออกที่ไหน · วิธีต่อแต่ละแบบ: [`INSTALL.md`](../INSTALL.md) ข้อ 5
ส่วนที่ไม่มีเครื่องของตัวเองจะพิมพ์ออกที่เครื่องเคาน์เตอร์

| ต่อแบบ | ใช้เมื่อ | ต้องเตรียม |
|---|---|---|
| **LAN / IP** | เครื่องพิมพ์อยู่จุดไหนในร้านก็ได้ | ล็อก IP เครื่องพิมพ์ที่เราเตอร์ · พอร์ตปกติ 9100 |
| **USB / Bluetooth ที่เครื่องเซิร์ฟเวอร์** | เครื่องพิมพ์อยู่ข้างเซิร์ฟเวอร์ | ลงไดรเวอร์ให้ขึ้นใน Printers & scanners ของ Windows ก่อน แล้วเลือกจากรายการ |
| **USB ที่ตู้คีออสก์** | บัตรคิวของคีออสก์เท่านั้น | ตั้งเป็นเครื่องพิมพ์หลักของตู้ · ตู้เปิดด้วย `screen-edge.bat` (เบราว์เซอร์ของตู้พิมพ์เอง) |

เครื่องพิมพ์ USB ที่เสียบเครื่องอื่น (นอกจากบัตรคิวของตู้) **ใช้ไม่ได้** — เซิร์ฟเวอร์เป็นคนส่งงานพิมพ์ ไม่ใช่เบราว์เซอร์

### ตั๋วไม่ออก

ครัวไม่ได้ตั๋วแต่จอครัวเห็นออเดอร์ = ปัญหาอยู่ที่เครื่องพิมพ์ ไม่ใช่ที่ระบบ

1. เช็กของจริงก่อน: **กระดาษหมด · ฝาเปิดไม่สนิท · สายหลุด · ไฟไม่เข้า**
2. หน้า **แคชเชียร์** ขึ้นแถบเตือนงานที่พิมพ์ไม่ออก → กด **ดูและพิมพ์ซ้ำ** → เลือกพิมพ์ซ้ำ (เครื่องเดิมหรือเครื่องอื่น) หรือไม่ต้องพิมพ์
3. ขอบขวาขาด / ตัวหนังสือเพี้ยน → แก้ความละเอียด (Epson TM‑T88 = 180 dpi) แล้วกด **พิมพ์ทดสอบ** ในฟอร์มเครื่องพิมพ์

ระบบลองเอง 3 ครั้งแล้วตกไปเครื่องสำรองให้อัตโนมัติ ถ้ายังไม่ได้ถึงจะขึ้นเป็น `FAILED`

> **ข้อจำกัดที่ต้องรู้**: เครื่องพิมพ์ความร้อนผ่าน TCP 9100 หรือ USB ไม่ตอบอะไรกลับ
> ระบบยืนยันได้แค่ว่า "ส่งถึงเครื่องแล้ว" **ไม่ใช่ว่ากระดาษออก**
> กระดาษหมดก็ขึ้น `DONE` เหมือนกัน — จึงต้องมีคนดูหน้าเครื่องอยู่ดี

## เปิดจอแต่ละเครื่อง (คีออสก์ · แคชเชียร์ · ครัว · จอคิว)

ใช้ `ops\screen-edge.bat` ไฟล์เดียวทุกเครื่อง — คัดลอกไปไว้ที่เครื่องนั้น แล้วดับเบิลคลิก (บนเครื่องเซิร์ฟเวอร์ใช้เมนู **เปิดจอบนเครื่องนี้**)

1. ครั้งแรกจะถาม **ที่อยู่เครื่องเซิร์ฟเวอร์** — ดูได้ที่ ⚙ › **อุปกรณ์ในเครือข่าย** (กล่องบนสุด เช่น `http://192.168.1.103:8080` มีปุ่มคัดลอก)
   หรือเมนู **ดูที่อยู่เครื่องเซิร์ฟเวอร์ (IP)** · พิมพ์แค่ IP ก็ได้ ระบบเติม `:8080` ให้ · จำไว้ที่เครื่องนั้น ครั้งต่อไปไม่ถาม · บนเครื่องเซิร์ฟเวอร์เองใช้ localhost ไม่ถาม
2. เลือกว่าเครื่องนี้เป็น 1 คีออสก์ · 2 แคชเชียร์ · 3 ครัว · 4 จอคิว (หรือสั่งตรง `screen-edge.bat display`)
3. อยากให้เปิดเองตอนเปิดเครื่อง: `screen-edge.bat display autostart` (แอนตี้ไวรัสบางตัวลบรายการ Startup — ถ้าหายให้สั่งใหม่)
4. จับคู่เครื่องด้วยรหัสที่ ⚙ › **อุปกรณ์ในเครือข่าย** › ปุ่ม **จับคู่** ในแถวของเครื่องนั้น

**ไฟล์นี้ทำอะไรให้:** เปิดเต็มจอ (แคชเชียร์เป็นหน้าต่างขยายเต็ม) · profile แยกต่อจอ · กล้องสแกนสลิปใช้ได้บน http ของร้าน · บัตรคิวพิมพ์ตรงไม่ถาม ·
**เสียงทำงานเองไม่ต้องกด** (จอคิว/ครัว/แคชเชียร์) แม้รีเฟรช อัปเดต หรือไฟดับ — เปิดด้วยเบราว์เซอร์ธรรมดา เสียงจะถูกบล็อกจนกว่าจะมีคนแตะจอ

| อาการ | แก้ |
|---|---|
| ขึ้น "Cannot reach …" / หน้าเชื่อมต่อไม่ได้ | เครื่องเซิร์ฟเวอร์ปิดอยู่ หรือ **IP เซิร์ฟเวอร์เปลี่ยน** (เราเตอร์แจกใหม่) → ดู IP ใหม่ที่ ⚙ › อุปกรณ์ในเครือข่าย แล้วสั่ง `screen-edge.bat ip` |
| จอคิวเงียบ มีปุ่ม "เปิดเสียงเรียกคิว" | ไม่ได้เปิดด้วย `screen-edge.bat` — ปิดแล้วเปิดใหม่ด้วยไฟล์นี้ |
| เครื่องขึ้น "หลุดการจับคู่" ในหน้าภาพรวม | จอค้างหน้าขอรหัส → จับคู่ใหม่ที่ ⚙ › อุปกรณ์ในเครือข่าย |

> ล็อก IP เครื่องเซิร์ฟเวอร์ที่เราเตอร์ (DHCP reservation) แล้วจะไม่ต้องกรอกใหม่อีกเลย

## กล้องสแกนสลิปที่คีออสก์

ลูกค้าจ่าย QR แล้วกด "โอนแล้ว · สแกนสลิป" → ยกจอมือถือที่เปิดสลิปให้กล้องอ่าน QR มุมสลิป
ระบบกันสลิปใบเดิมใช้ซ้ำ แล้วอ่านภาพสลิป: **ยอด · วันเวลา · บัญชีผู้รับ ผ่านครบ → ปิดบิลและส่งเข้าครัวเอง**
ไม่ผ่าน/อ่านไม่ออก → รอแคชเชียร์ยืนยัน (ระบบไม่ได้ตรวจกับธนาคาร — แคชเชียร์ควรดูแอปธนาคารร้านเป็นระยะ)

ตั้งเครื่องคีออสก์และตำแหน่งกล้อง: [`INSTALL.md`](../INSTALL.md) ข้อ 6.1 — เปิดด้วย `screen-edge.bat kiosk` **เท่านั้น** · เปิดเองตอนบูต: `screen-edge.bat kiosk autostart`

**ทำไมต้องเปิดด้วยไฟล์นี้:** เบราว์เซอร์ยอมให้ใช้กล้องเฉพาะหน้าเว็บ https เซิร์ฟเวอร์ร้านเป็น http
ไฟล์นี้บอกเบราว์เซอร์ให้เชื่อ *เฉพาะ* เซิร์ฟเวอร์ร้าน และอนุญาตกล้องให้อัตโนมัติ (ไม่มีคนยืนกด "อนุญาต")
ถ้าเปิดคีออสก์แบบอื่น หน้าสแกนจะขึ้น "กล้องของเครื่องนี้ยังใช้ไม่ได้" แล้วให้ลูกค้าแจ้งพนักงาน — ร้านยังขายได้

| อาการ | แก้ |
|---|---|
| ขึ้น "กล้องของเครื่องนี้ยังใช้ไม่ได้" | ไม่ได้เปิดด้วย `screen-edge.bat` หรือ IP ที่บันทึกไว้ไม่ตรงกับที่เปิดอยู่ (`screen-edge.bat ip`) |
| ขึ้น "เปิดกล้องไม่ได้" | กล้องหลุด / โปรแกรมอื่นใช้กล้องอยู่ |
| ขึ้น "มีแสงสะท้อนบนจอมือถือ" บ่อย | ไฟเพดาน/หน้าต่างสะท้อนเข้ากล้อง — ก้มกล้องลง 10–15° หรือย้ายไฟ ดู [`INSTALL.md`](../INSTALL.md) ข้อ 6.1 |
| สลิปขึ้นแดง "ไม่ใช่บัญชีร้าน" ทั้งที่จ่ายถูก | ชื่อ/เลขบัญชีใน ⚙ › **ข้อมูลร้าน** ไม่ตรงกับที่ขึ้นบนสลิป — แก้ให้ตรง |
| สแกนนานไม่ติด / ภาพสลิปเบลอบ่อย | ใช้เว็บแคมที่ **โฟกัสอัตโนมัติ (autofocus)** 1080p — กล้องโฟกัสตายตัวจะเบลอที่ระยะ 20–30 ซม. เสมอ · ไม่หันกล้องรับไฟเพดานตรง ๆ |
| "สลิปนี้ถูกใช้ชำระออเดอร์อื่นไปแล้ว" | ลูกค้าเอาสลิปเก่ามาใช้ — ดูประวัติได้ที่ audit (`SLIP_REJECTED`) |

### ตัวอ่านสลิป (OCR)

กล้องถ่ายภาพสลิปเก็บไว้ แล้วตัวอ่านสลิป (`ocr-svc\`) อ่าน **ยอดเงินกับวันที่** จากภาพ
มี 2 แบบ: **แบบเร็ว OpenVINO** (ค่าเริ่มต้นเมื่อติดตั้งไว้ ~1 วิ/ใบ) และ **แบบปกติ PaddleOCR** (~3 วิ/ใบ) — แบบเร็วเปิดไม่ขึ้น 2 ครั้ง ระบบสลับเป็นแบบปกติเอง
บังคับใช้แบบปกติ: เพิ่ม `CF_OCR_ENGINE=paddle` ใน `.env` → **รีสตาร์ทระบบ** · เทียบความเร็วกับสลิปของร้าน: เมนู **วัดความเร็วตัวอ่านสลิป**

การ์ดแคชเชียร์ขึ้นผลเอง: เขียว = ตรง · **แดง = ยอด/วันที่ไม่ตรง** · เทา = อ่านไม่ออก
ตอนอ่าน QR ได้ กล้องเก็บภาพต่ออีก ~0.6 วินาทีแล้วเลือกภาพที่คมที่สุด · ถ้า OCR อ่านยอดไม่ออก
หรือไม่เห็นวันที่ (ถือให้กล้องเห็นแค่ครึ่งล่าง) คีออสก์โชว์ภาพที่ถ่ายได้ + บอกว่าต้องแก้อะไร
ลูกค้ากด "ถ่ายใหม่" ได้เรื่อย ๆ หรือ "ส่งให้พนักงานตรวจ" · ทิ้งไว้ 60 วิส่งให้พนักงานเอง
คีออสก์รอผลนี้ด้วย (นานสุด 15 วินาที): ยอด/วันที่ไม่ตรง → ขึ้นกล่องแดงบอกลูกค้าให้สแกนใบที่ถูก
หรือแจ้งพนักงาน · อ่านไม่ออก/ตัวอ่านไม่ตอบ → ไปรอแคชเชียร์ตามปกติ (ลูกค้าไม่ติดหน้าเครื่อง)
ผ่านครบทั้ง 3 อย่าง ระบบปิดบิลเอง (ตั้งแต่ 14/10/2569) · ไม่ครบ คนเป็นผู้ตัดสิน
ดูว่าระบบเดาถูกแค่ไหนเทียบกับที่แคชเชียร์ตัดสิน: **รายงาน** › ความแม่นการตรวจสลิป

ติดตั้งมากับ `ops\cafeflow.bat` แล้ว · ลงเองใหม่ (ต้องมีเน็ต): `ocr-svc\setup.bat` แล้ว `ocr-svc\setup-openvino.bat` → **รีสตาร์ทระบบ**
เปิดพร้อมระบบโดย `ops\run-cafeflow.ps1` (ถ้าติดตั้งไว้) · เช็กว่าทำงาน: เมนู **ตรวจสถานะระบบ** หรือ `curl.exe http://127.0.0.1:5101/health` · ใช้แรม ~1 GB · อ่านทีละใบ

**ถ้าตัวอ่านสลิปไม่ได้เปิด ร้านขายได้ปกติ** — สลิปรอในคิว แล้วอ่านต่อเองเมื่อเปิดกลับมา
ภาพสลิปอยู่ที่ `data\slips\` (มีชื่อ/เลขบัญชีบางส่วนของลูกค้า ห้ามแชร์ออกนอกร้าน)
การสำรองข้อมูลคัดลอก `data\` ไปที่ `backup\data\` ด้วย (เฉพาะไฟล์ใหม่) · `offsite.sh` คัดลอกตามไป · `restore.sh` คืนให้

## คำสั่งที่ใช้บ่อย

PowerShell ที่เครื่องเซิร์ฟเวอร์ ในโฟลเดอร์ `D:\cafeflow`:
```powershell
# ดูออเดอร์ที่ยังไม่จบ
docker exec -it cafeflow-db psql -U cafeflow -d cafeflow -c "SELECT order_no, status, total FROM cf_order WHERE status NOT IN ('COMPLETED','CANCELLED','VOIDED','REFUNDED') ORDER BY created_at;"

# ดูรอบขายที่เปิดอยู่
docker exec -it cafeflow-db psql -U cafeflow -d cafeflow -c "SELECT id, opened_at, opening_cash FROM shift WHERE status = 'OPEN';"

# ดู log สด ๆ
Get-Content logs\api.log -Tail 50 -Wait      # API (รันนอก container — log อยู่ใน logs\)
Get-Content logs\api.err.log -Tail 50        # ข้อผิดพลาดของ API
docker compose logs -f db                    # ฐานข้อมูล

# งานที่ตั้งไว้ใน Task Scheduler
schtasks /Query /TN CafeFlow /V /FO LIST
schtasks /Query /TN "CafeFlow Backup" /V /FO LIST
```

**ห้ามแก้ข้อมูลด้วย SQL ตรง ๆ ถ้าไม่จำเป็นจริง ๆ** — ทุกการเปลี่ยนสถานะที่ผ่าน
ระบบจะมี audit log กำกับ แต่การแก้ตรงในฐานจะไม่มี และตรวจย้อนหลังไม่ได้ว่าใครทำ
